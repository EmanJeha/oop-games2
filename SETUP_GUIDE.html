OOP Games 2 · Methods (Grade 10): setup guide

You already set up Firebase for the insertion sort games, so skip steps 1 and 2: config.js already has your Firebase settings. These games (Session 2: methods, slides 21–41) keep their own scores, so they never mix with your Session 1 OOP games or the sorting games.

1Create the free database (Firebase)

  1. Go to console.firebase.google.com and sign in with a Google account.
  2. Click Create a project. Name it, for example, insertion-games. Turn Google Analytics off, then create the project.
  3. In the left menu open Build → Realtime Database and click Create Database. Pick a location (Belgium, europe-west1, is closest to Saudi Arabia). Choose Start in test mode and click Enable.
  4. Open the Rules tab, delete what is there, paste the rules below, and click Publish.
{
  "rules": {
    "sessions": {
      ".read": true,
      ".write": true
    }
  }
}

Test mode stops working after 30 days. These rules keep it working. The games only store pair names, scores and exit-ticket answers, so use first names only.

2Copy your settings into config.js

  1. In Firebase click the gear icon → Project settings. Scroll to Your apps and click the web icon </>.
  2. Give it any nickname (for example games) and click Register app. You don't need Firebase Hosting.
  3. Firebase shows a block called firebaseConfig. Open config.js from this folder in Notepad and replace each PASTE… value with the matching value. Keep the quotes.
  4. Check databaseURL. It must match the address shown at the top of the Realtime Database page (it ends in firebaseio.com or firebasedatabase.app). If Firebase didn't include it, copy it from there.

The apiKey in a Firebase web app is meant to be public, so it is fine to put it on GitHub.

3Put the games on GitHub Pages

If you name the repository something other than oop-games2, change the SITE_URL line at the bottom of config.js to match.

  1. On github.com click New repository. Name it oop-games2, set it to Public, and create it.
  2. Click uploading an existing file. Drag in all the files from this folder (not the folder itself), including your edited config.js. Click Commit changes.
  3. Open Settings → Pages. Under Build and deployment choose Deploy from a branch, branch main, folder / (root), and click Save.
  4. Wait 1–2 minutes and refresh. GitHub shows your site address, like https://emanjeha.github.io/oop-games2/

4Run it in class

Smart boardOpen https://emanjeha.github.io/oop-games2/board.html?game=warmup and press Full screen. The QR code and join link appear on the left.
StudentsOne device per pair. They scan the QR code, type both names (for example Sara & Noura) and press Join. Each pair appears on the board straight away.
StartPress Start game. Every pair gets the questions on their own device. The board shows each pair's score, progress and which question they're on, and re-ranks live.
EndPress End game (or wait until everyone finishes and press Show results). You get the podium and a chart of which questions the class found hardest.
Wrap-upAt the end of the lesson press Switch to Method Masters. The QR changes to the wrap-up game. After it ends, press Show answers to read every pair's exit ticket.
Next classPress New round (click twice). This clears the board for a fresh group.

Students can bookmark https://emanjeha.github.io/oop-games2/ and choose a game there, but the QR code from the board is quickest.

5Good to know

  • Practice mode: until config.js is filled in, students can still play, but nothing appears on the board.
  • Refreshing is safe: if a pair's page reloads, they continue from where they were.
  • Late pairs can join at any time while the game is live.
  • Scoring: 100 points per correct answer, plus up to 50 for speed. In the warm-up, cracking the mystery topic is worth +200.
  • Changing questions: edit questions.js in GitHub (pencil icon) and commit. Keep the same structure.
  • Who can control the board: anyone who opens board.html can press Start or End, so don't share that link with students.
